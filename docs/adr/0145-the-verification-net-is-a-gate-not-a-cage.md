# ADR 0145: 検証網は門であって檻ではない——切断参照を受入の一点で数える

- 状態: 採択（2026-07-28）
- 関連: [ADR 0138](0138-transform-acceptance-five-conditions.md)（五条件）、
  [ADR 0143](0143-io-sentinel-is-an-early-warning-not-a-finding.md)・
  [ADR 0144](0144-prediction-excess-is-not-a-conflict.md)（境界は予測であって制約ではない）
- 計画: [docs/plan_seam-cost.md](../plan_seam-cost.md)

## 文脈

seam 変換は symbol を別ファイルへ移す。移した先の code が、残余面に留まった symbol
（module 変数・非公開関数）へ束縛なしで言及していても、**module の読み込みは通る**。
ReferenceError は実行時にしか出ないので、focused test が当該経路を通らなければ、
壊れた変換が五条件を通過して採用される——検証が「同等」と主張する静かな破壊である。

静かな破壊が普通の破壊と次元が違うのは1点だけである。**壊して直すループは「壊れたら分かる」
という前提の上で回る。検証者の偽陽性はその前提そのものを壊す。** 直す費用ではなく、後日
別の顔で現れた症状を原因まで遡る費用が本体になり、そのとき「検証済み」の記録が嘘として
残っていて調査を誤導する。

## 裁定

### 1. 切断参照を数え、`behavior_equivalent` の中身として落とす

変換後 worktree の fresh index から残余面の symbol 一覧を抽出精度で取り
（`lattice-sensor file-nodes`）、移した各面の本文が「残余面に留まった名前」へ
定義もimportも無しに言及していれば、`severed_reference:<file>:<name>` として
`behavior_equivalent` を落とす。

- **`unresolved_refs` は使わない。** bare 参照の切断はそこに記録されないことを実測で確認した
  （builtin 呼び出しは載るが、未束縛の identifier 読みは載らない）。計画は unresolved_refs の
  集合差分を予定していたが、実験が primitive を訂正した。
- ノード生成は value-ref 辺の名前フィルタに影響されないので、**全小文字の module 変数も
  この網には映る**。
- 検査は保守的である。言及の判定は text 一致なので、文字列・comment 内の同名語も切断の
  疑いとして数える——見逃す方向でなく誤検出の方向へ倒す（fail closed）。誤検出の実害は
  「変換が直列化へ落ちる」であり、安全側で吸収される。

### 2. 網は門であって檻ではない

- **検査は受入の一点だけ。** 完成した変換の成果物に対して、隔離 worktree の中、五条件と
  同じ場所で一度だけ行う。**過程を監視しない**——作業中の worker には何も言わない。
- **失敗は不認定であって拒否ではない。** 理由と対象（file・symbol 名）を返す。再試行は
  安価で、回数・失敗は誰にも記録されない。
- **採点しない。** 「この worker は N 回失敗した」の類の台帳を装置は持たない。履歴採点は
  宣言の過大化・回避行動・過剰直列化を生む——境界を予測から事実上の制約へ戻してしまう。
- 網は賢い実行者を縛るのではなく解放する。機械的な確認を装置が引き受けるから、
  実行者（AI・スクリプトの別を問わず）は設計判断に知能を使える。

### 3. 実行者に依存しない

網は変換の**成果物**を見る。装置の ESM 変換器が移し忘れても、AI が手で移し忘れても、
同じ網にかかる。検証の下限が実行者の種類に依存しない。

## この裁定が主張しないこと

- **export 面の比較（`compareExportSurface`）が多言語になった、とは言っていない。**
  あれは ESM 構文を正規表現で読む JS/TS 限定の検査であり、他言語の source に対しては
  実質空である。網の言語非依存部は切断参照の計数が担い、それは sensor が抽出できる言語で
  効く。どちらがどこまで見ているかは code が明示する。
- **グラフの盲点が消えた、とは言っていない。** 網は fresh index の symbol 一覧に立つ。
  sensor が抽出しない依存（動的参照・別 repository・実行時 path）は映らない。
- **AI が変換して直接 recompile（`seam_split`）へ出す経路を網が覆う、とは言っていない。**
  五条件は `run seam resolve` の隔離変換で走る。手動変換＋recompile の経路は
  `verifySeamSplitSuccessor`（構造検査）だけが見ており、そこへの網の拡張は別課題として
  backlog に残す。
