# ADR 0068 — 依存線はカードとカードの間を通り、カードの下を通らない

- Status: Accepted
- Date: 2026-07-26
- Supersedes: ADR 0066 Decision 7「依存edgeを持たないToDoは段の中で折り返して格子に並べる。edgeを持つ
  ToDoは段の先頭行に残す（経路計算は同じ段の両端が同じ基準線に乗る前提を持つ）」

## Context

工程図の唯一の仕事は依存の順序を伝えることである。その線が読めない状態が3つ同時に起きていた。

**線が図の全幅を往復していた。** 段を跳ぶ辺は、図全体の右端の外に置いた回廊まで走り、そこで縦移動して
から戻っていた。回廊は右側にしか存在せず、出発と到着の位置に関係なく全ての段跳びがそこを通る。隣り
合うカード同士の局所的な1 hopが図の全幅を往復する線として描かれ、どの線がどこへ繋がるのか追えない。
bingoの実store（scope all・139辺）で総配線長981,896px、カード右端より外へ出る線分222本、図幅の約25%が
回廊だけのために使われていた。

**真下へ繋ぐ線が折れていた。** 同じ列の隣接段を繋ぐ辺は、出発ポートと到着ポートが同じ(帯,列)の取り付け
位置集合を奪い合い、別々の枠を取っていた。まっすぐ引ける線が12pxずれた2本の縦線と短い横棒になり、
工程が真下にあるのに段差付きに見えた。

**線がカードの下に隠れ、別の依存として読めた。** dotagentsの実storeで、実在する`fm-0671 → fm-0672`の辺の
途中に`fm-0640`の箱が置かれ、線の上半分が隠れた。残った下半分が「`fm-0640`から出た矢印」に見え、
オーナーが「0640が終わっていないのに0672が先走っている」と誤読した。`fm-0640`は依存の辺を1本も持たない
独立ToDoであり、工程順の違反は起きていない。図だけが誤った順序を伝えた。

当初この誤読の原因を「経路が右側回廊しか使わずnode回避を持たないこと」と記録していたが、実測で誤りと
判明した。箱を貫く線分を数えると貫通567箱すべてがwave 0の独立ToDoで、犯人は段跳び経路ではなく
**カード下端から帯へ降りるport stub**だった。段跳び経路が箱を貫いた例は旧配線でも0件である。右側回廊が
図の外を通るため偶然当たらなかっただけで、node回避の不在は別の形で現れていた。

機構はADR 0066 Decision 7そのものだった。独立ToDoを接続済みToDoの下の行へ折り返す一方で、接続済み
カードのport stubは段全体の下にある帯まで垂直に降りる。同じ列に落ちた独立カードは必ず貫かれる。
「edgeを持つToDoは段の先頭行に残す」という規約が、そのまま欠陥の定義になっていた。

## Decision

1. **段を跳ぶ辺は、両端カードの間にある列境界の縦チャネルを通る。** カードは全段・全行で同じ列グリッドに
   載るため、列と列の間はどの段でもカードが無い。候補は両端の列の間にある境界（同一列なら左右の隣接
   境界）とし、最も空いているものを選ぶ。図の右端の外に出る回廊を持たない。
2. **チャネル幅は通行本数に応じて広げる。** 通行の無い境界は24pxのままとする。容量は幅が伸びて吸収する
   ため溢れが定義上存在せず、fallback経路を持たない。
3. **同じ列の隣接段を繋ぐ辺は、出発と到着で取り付け枠を1つ共有する。** 両端の縦線は帯の中で1点で接する
   だけで重ならない。他の辺との間の排他は保つ。
4. **依存edgeを持たないToDoのブロックは、接続済みToDoの上へ置く。** 接続済みToDoが段の最下行になる。
   独立ToDoは辺を持たない以上入辺も持たないので必ず第0段に入り、第0段へは何も到着しない。上へ置けば
   貫く線が構造的に存在しなくなる。ADR 0066 Decision 7の折り返し格子そのものは維持する。
5. **経路がカードの矩形の内部を通らないことを機械gateで固定する。** 全経路×全カードの非交差を検査し、
   除外を設けない。

## Consequences

- 実測（bingo実store・scope all・139辺）: 総配線長 981,896→303,596px、幅 7044→5988px、カード右端より
  外へ出る線分 222→0本。
- 実測（貫通した箱の数）: dotagents 663→0、bingo 2→0。
- 段跳びの縦線が図の内側を通るため、配線帯の横線と交わる回数は増える。これは実在する交差であり、
  非接触の交差は従来どおり半円bridgeで描く。回廊が外を通っていた時に交差が少なかったのは、線が図から
  出ていたからにすぎない。
- 列間ギャップが通行量ぶん広がるため、カード群の横幅は増える。回廊の撤去分がそれを上回り、図全体の幅は
  縮む（bingoで7044→5988）。
- チャネル割当はwaveと列位置だけに依存し座標に依存しないため、占有数→ギャップ幅→座標の一方向計算で
  閉じる。branch keyのソート順greedyであり、同一入力から同一出力になる決定性は保つ。
- 第0段の見え方が変わる。依存を持たないToDoが上、依存を持つToDoが下になる。縦方向は依存段階であって
  時間ではないという既存の読み方は変わらない。
