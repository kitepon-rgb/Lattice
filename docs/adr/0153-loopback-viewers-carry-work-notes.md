# ADR 0153: loopbackの工程表は作業記録を表示する

- Status: Accepted
- Date: 2026-08-02
- Supersedes: ADR 0149 Decision 8（公開wrapperによるnote本文の一律除外）

## Context

ADR 0149 Decision 8は「公開面は初版でnote本文を出さない」と決め、`todo gantt serve`と常駐dashboardを
共通の公開wrapperへ通した。判断そのものは正しかったが、適用範囲が実態とずれた。この2面はどちらも
loopbackへ閉じており、読むのは作業者本人である。repo外へHTMLを出す配信面は当時も今も存在しない。

結果として、renderNoteContextは製品経路から到達不能になった。実測では1 planあたり十数件・数十KBの
作業記録が画面へ1文字も出ておらず、記録を読むにはCLIへ戻るしかなかった。着手判断の材料が装置の中に
ありながら、装置の表示面がそれを描かない状態だった。

同じ詳細ペインで、並列可否の欄も記録が無いplanでは枠ごと消えていた。消えた欄は「競合なし」と読まれる。
未検査は競合の不在ではないという契約（ADR 0127）が、最も警告を要する状態で沈黙していた。

## Decision

1. **loopbackへ閉じた面は作業記録を表示する。** `todo gantt serve`と常駐dashboardはnote本文込みで描く。
   除外の対象はrepo外へHTMLを出す公開配信面だけとする。
2. **公開配信面の入口は残す。** `includeNotes: false`を強制する入口を維持し、そこへ通す面が生えるまで
   使わない。入口が使われていないことを、実態としてコメントで述べる。
   （0.50.0のオーナー裁定が上書き: 公開面もnote込みが正となり、`renderPublicTodoGanttForProject`と
   `includeNotes`配管は削除した。除外の入口はもう存在しない。）
3. **表示の有無ではなく配線を守る。** loopbackの面が公開入口へ戻らないことを、実サーバを起こして
   HTMLを取得するtestで固定する。renderNoteContextへ到達しない配線を再びgreenにしない。
4. **並列可否は完了工程を除き必ず述べる。** 記録が無い・失効・旧versionの時は「未検査」とその理由、
   判定へ進むcompile commandを示す。ready frontierの外に居る工程も黙らせない——着手済の工程は自分が
   塞いでいる着手候補を示し、まだ候補でない工程は判定前だと述べる。
5. **前提工程・後続工程は相手の状態を添える。** 相手ごとにstoreから引き、選択中の工程の状態を流用しない。

## Consequences

- 作業者はToDoの判断材料——設計メモ、作業記録、前提と後続の状態、並列可否——を1つの詳細ペインで読める。
- note artifactはgit trackedであり、この変更で新たな露出経路は増えない。loopbackの面は元々repoを
  読める者しか到達できない。
- 公開配信面を作る時は、ADR 0149 Decision 8の除外契約がそのまま適用される。改めての裁定は要らない。
  （0.50.0で無効: 除外契約そのものが廃止され、どの面も記録込みで描く。）
- 秘密をnoteへ書かない運用規律は変わらない。表示面が増えたことを、記録内容の緩和と読み替えない。
