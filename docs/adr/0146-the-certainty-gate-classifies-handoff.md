# ADR 0146: 確実の門——機械変換の前提を正典化し、手渡しを分類する

- 状態: 採択（2026-07-28）
- 関連: [ADR 0138](0138-transform-acceptance-five-conditions.md)（五条件）、
  [ADR 0145](0145-the-verification-net-is-a-gate-not-a-cage.md)（検証網）
- 計画: [docs/plan_seam-cost.md](../plan_seam-cost.md)

## 文脈

リファクタリングの主体は Lattice を操作する AI である（オーナー裁定）。スクリプト変換が
許されるのは**確実にできる内容だけ**——チャレンジは駄目、怪しければ AI へ（オーナー裁定）。

ESM 変換器は元から fail closed で、導出・照会・書き換え・五条件の各段が typed 理由で
拒否する。欠けていたのは2つ: 前提が**一覧として読めない**こと（条件がコードに散在し、
機械が何を引き受けているかを事前に知る面が無い）、拒否の後で**次に誰が動くべきか**が
返らないこと（直列化へ落ちるだけで、宣言を直せば機械で通るのか、AI が変換すべきなのかの
区別が無い）。

## 裁定

1. **前提の正典は `SEAM_GATE_PRECONDITIONS`**（`src/seam-gate.mjs`）。8条件——入力の形、
   所有の宣言と排他、閉包の観測完結、共有面の非逆依存、行範囲の確定と非重複、挙動保存
   （公開面＋切断参照）、test と index の通過、並列性の獲得。各段の typed 理由と prefix で
   対応する。
2. **門は手渡しを分類する。可否は決めない。** 拒否理由を `fix_declaration`（宣言を直して
   再提出すれば機械で通りうる）と `hand_to_ai`（機械の変換能力の外＝AI が変換すべき）へ
   分け、`lattice.runtime_seam_resolution.v2` の `gate` として返す。
3. **未知の理由は確実側へ丸めない。** 分類できない拒否は `unrecognized` として返し、
   手渡しは安全側（`hand_to_ai`）に倒す。理由の語彙が増えた時、黙って「確実」へ倒れる
   壊れ方を防ぐ。対応の突き合わせ test が語彙と正典の同期を強制する。

## この裁定が主張しないこと

- 新しい拒否条件を追加していない。門は既存の fail-closed 挙動の**読める面**であり、
  変換の通り方は変わらない。
- `fix_declaration` は「機械で必ず通る」ではない。直した宣言で再提出した先にはまた門がある。
