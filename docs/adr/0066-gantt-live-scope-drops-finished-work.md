# ADR 0066 — 工程図の既定表示は完走した工程を描かない

- Status: Accepted
- Date: 2026-07-25
- Supersedes: ADR 0053「可読性は折畳み・段階開示（G3）が担う」「既定表示はplan/lane折畳み＋最長依存鎖と
  active setを常時展開」

## Context

storeは完了ToDoをplan revisionを越えて運ぶため、図は単調に増える。dotagentsの実storeでは781 ToDoのうち
773が完了しており、既定表示が全件を描いていた。読む側が必要とするのは「いま着手できるもの」だが、
画面はほぼ全て履歴で埋まっていた。

段階的に3つの表示規約を試し、いずれも実測で棄却した。

1. **連結成分ごとの畳み込みnode**（0.12.11）: 完了ToDoが互いに依存を宣言していないstoreでは1件1nodeへ
   空振りする。767件が592nodeにしかならず、箱の数は減らないまま題名だけが消えた。
2. **plan単位の畳み込みnode**（0.12.13）: 767件が9nodeになったが、まとめnodeも1個につき1列を占める。
   完走したplanが9つあれば9列が履歴のためだけに残り、図は生きた工程の何倍もの幅を保った。
3. **描かない**（0.12.14）: 幅は生きた工程ぶんへ戻った。

あわせて、図の幾何そのものが場所を捨てていた。段間隔は図全体で最も混雑した配線帯に合わせて全段へ一律
適用され、実storeでは段間隔704pxのうち箱は68px＝縦の90%が空白だった。前提を持たないToDoは全て第0段へ
入るため、依存宣言の少ないstoreでは567件が横一列に並んだ。

## Decision

1. 既定scope`live`は、後続に作業中・未着手が残っていない完了ToDoを**図から除く**。まとめnode・
   placeholder・空の列を代わりに置かない。生きたToDoとその直接の前提ToDoは必ず描く。
2. 除いたToDoの情報は図の外が持つ。凡例が件数を示し、右ペインの「全工程」がplanごとの畳んだ一覧として
   全件を保持し、各ToDoの詳細は除外後も開ける。
3. 各ToDoの前提・後続は**除外前のグラフ**から表示する。図に描かれていない相手には「（図では非表示）」を
   添える。描画のための投影が、事実の記述を縮めることを許さない。
4. 総数・進捗・最長依存鎖・ready frontierは除外前の全工程で数える。
5. 件数バッジは展開の入口を兼ねる。押すと全工程を描いた図へ切り替わる。生成物は`file://`でも開くため、
   展開図は同じページへ同梱する。除いたToDoが無い場合はバッジも同梱も出さない。
6. 配線帯の高さは、その帯を実際に通るedge数で決める。図全体の最大値を全段へ適用しない。
7. 依存edgeを持たないToDoは段の中で折り返して格子に並べる。edgeを持つToDoは段の先頭行に残す
   （経路計算は同じ段の両端が同じ基準線に乗る前提を持つ）。

## Consequences

- 実測（dotagents 781 ToDo）: 描画node 781→14、幅 182,656→14,824px、高さ 36,004→8,156px。
- 除外は描画時に確定し、クライアント側で部分展開する経路は持たない。展開は同梱した全体図への切替だけ。
- 展開図を同梱するぶんHTMLが増える（実storeで+1.2MB）。除外が発生していないprojectには増分が無い。
- 「依存を1本も持つToDoが多数ある」ことが図に現れる。dotagentsでは781件中567件がそれに当たり、
  依存宣言の不足そのものが可視化される。図の側でこれ以上隠さない。
- ADR 0053の折畳み前提を採らない。ToDo単位の可読性はscope投影と右ペインの一覧が担う。
