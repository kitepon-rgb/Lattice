- ~~**依存の辺が箱の下を通り、別の依存として読める（2026-07-25・実被害あり）**~~
  （2026-07-26消化。原因を実測で特定し直したうえで修理した。以下は経緯の記録）
  dotagents実storeで、実在する`fm-0671 → fm-0672`の辺の途中に`fm-0640`の箱が置かれ、
  線の上半分が隠れた。残った下半分が「`fm-0640`から出た矢印」に見え、オーナーが
  「0640が終わっていないのに0672が先走っている」と誤読した。`fm-0640`は依存の辺を
  1本も持たない独立ToDoであり、工程順の違反は起きていない。**図だけが誤った順序を伝えた。**
  工程図の唯一の仕事は順序を伝えることなので、これは見た目の粗さではなく機能欠陥として扱う。

  当初「経路が右側回廊しか使わずnode回避が無いこと」を原因と記録したが、2026-07-26の実測で
  **誤りと判明した**。dotagents実store（scope all・218辺）で箱を貫く線分を数えると、
  貫通は567箱すべてが**wave 0の独立ToDo**で、原因は段をまたぐ経路ではなく
  **カード下端から帯へ降りるport stub**だった。段をまたぐ経路が箱を貫いた例は
  旧配線でも0件である（右側回廊が図の外を通るため偶然当たらなかった）。

  機構: 独立ToDoは辺を持たないので必ずwave 0に入り、`src/todo-gantt-layout.mjs`の段内折り返し
  （`LOOSE_COLUMNS_MINIMUM`のブロック）で接続済みカードの**真下の行**へ並ぶ。一方、接続済み
  カードのport stubは段全体の下にある帯まで垂直に降りるため、同じ列に落ちた独立カードを貫く。

  修理: 独立ToDoのブロックをwave 0の接続済み行の**上**へ移した。wave 0には到着stubが存在しない
  （入辺を持たないからwave 0になる）ので、上へ置けば貫通経路が構造的に消える。段をまたぐ縦チャネルは
  列間ギャップを通るため元から無関係。実測で貫通はdotagents 663→0、bingo 2→0。
  回帰testは`test/todo-gantt-layout.test.mjs`の`assertNoRouteEntersBox`が全経路×全カードを検査し、
  除外は無い。
