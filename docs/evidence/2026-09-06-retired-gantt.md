# 退役工程による工程表500の原因

movieの研究工程を退役した後、公開工程表が `TODO_LAYOUT_INVALID_INPUT` を返した。
修正前の共通rendererへ実storeを渡しても `chain projection references an absent task` を再現した。
ネットワーク中継やWindows固有の起動処理を通さずに発生する。

`renderTodoGanttForProject` は退役済み工程を含むplanから最長経路を作っていた。
`normalizeInput` は退役済み工程とその辺を描画から除いていたため、同じ内部データを異なる集合へ
変換し、その食い違いを後段の検査が異常入力と判定していた。退役操作とstoreは正常だった。

共通の描画処理で正規化したgraphから経路を直接導出する。別の経路入力、上位・階層表示での重複計算、
同じ内部graphを別入力として照合する処理を撤去した。データの手補正、エラー握りつぶし、再試行、
Windows限定の分岐は加えていない。退役工程に残るフェーズ依存も実行可能性の判定対象から除く。

最長経路を退役させた小さなfixtureで、修正前の失敗と修正後の通過を確認した。
movieの実storeも修正後は2計画のHTMLを生成できた。これは公開配信の完了とは分けて記録する。

関連する工程図112試験は、修正途中の参照漏れで失敗したrenderer・CLI試験を修理後に再実行して通過を確認した。
工程移行18試験、工程保存の関連試験、文書検査、182ファイルの構文検査も確認した。
移行試験は製品test harnessの環境を使用する。直接起動時に実dashboardの配信結果がstderrへ加わった
失敗を製品の修正理由にはせず、生成した試験用登録を正規入口から除去した。
