# Lattice v0.6.4 status performance evidence

- 対象: `@quolu/lattice@0.6.4`
- 実施日: 2026-07-19 JST
- 実データ: dotagents 7 plans / 653 active tasks / 3 excluded tombstones

## 再現

global `0.6.3`の`lattice todo status`は実storeで次の時間を要し、内部5秒timeoutを持つ
Claude SessionStart hookが`status取得が期限超過`を返した。

```text
real 8.41
user 3.57
sys  2.96
```

原因は、503件のhistorical import done taskのread-time evidence検証が、同じsource commit/fileに対して
taskごとに`git cat-file -t <commit>`、`git cat-file -t <commit:file>`、
`git cat-file blob <commit:file>`を起動していたことだった。

## 修正

`readTodoStore`呼出しごとに空のcacheを作り、そのread中だけsource commitとblobを再利用する。
cacheはstore readを跨がず、次のreadではGit objectを再検証する。journal replay、snapshot比較、
source line digest、checkbox parser、write時のfail-closed検証は変更していない。

回帰testは同じpinned sourceを持つ2 taskのreadでGit subprocessを計測し、commit type 1回、
blob type 1回、blob read 1回の合計3回に固定する。
