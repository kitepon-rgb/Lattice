## 公開操作

1. H承認の恒久範囲をAGENTS.mdへ限定付きで固定し、0.58.1へversion bumpした。
2. 独立反証で、旧4commitだけではversion衝突・main未着地・完全gate未完了であることを確認した。
3. 0.58.1 release commitで完全gate、production audit、実prepackを通した。
4. `origin/main`へfast-forward pushし、clean detached worktreeの祖先gate通過後だけpublishした。
5. registry metadataの初回取得は伝播中で0.58.1を返さなかった。独立した再問い合わせでversion、latest、
   SHA-1、integrityを確認し、単一試行を成功根拠にしなかった。
6. 公開npmをversion pinでMacへglobal installし、dashboard登録とbridge kickstartを行った。
7. dashboard health、bridge status、公開HTTPS、Peertableの保存projectionを確認した。
8. Peertable HEADの一時worktreeへ現ToDo storeを複製し、既存binding／compileを除いた状態で公開版compileを
   実行した。結果はconsistent／enabled／finding 0。元Peertable storeとWIPは変更していない。

## 実行中に見つけた案内不足

clean release worktreeへ依存を実directoryとして移す時、`cp -R -L`では内部の`.bin/tsc` symlinkまで
展開され、相対参照が壊れた。外側symlinkの参照先を`realpath`し、そのdirectoryを`cp -R`する形に
修正してpackを成功させた。再発防止を配備記録のpublish手順へ還流した。

Peertable compile smokeでは、最初の試行が一時worktreeを作った後も元cwdで実行され、元storeの不変bindingに
正しく拒否された。次の試行は旧actor変数が拒否され、正規の3分割actor環境を指定して成功した。どちらも
元storeへ書込みは無い。一時worktreeとcopyは完了後にTrashへ退避し、worktree登録から除去した。

## Rollback

CLI起動不能、dashboard HTTP不達、bridge heartbeat拒否、または0.58.1固有のデータ破壊が確認された場合、
`npm install -g @quolu/lattice@0.58.0 --prefer-online`でMacを戻し、Lattice実repoのstatus登録と
`launchctl kickstart -k "gui/$(id -u)/dev.kitepon.lattice.bridge"`を再実行する。npm unpublish、force push、
remote mainの履歴巻き戻しは行わない。今回はrollback条件に該当しなかった。
