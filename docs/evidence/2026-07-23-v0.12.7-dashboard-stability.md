# v0.12.7 public dashboard安定化証拠

## 対象

- source commit: `a8c16cae51c505dae355912c2e1f2b3f57d645b8`
- npm package: `@quolu/lattice@0.12.7`
- npm integrity: `sha512-MavfGnuBxf0ZHw7kBHHSUWACZ64p2PA0vdflI3R7peHSwtD0sEUR9sYepFmGrJDWlW150a3W7K9EKGPWXNT2Pg==`
- 取得日: 2026-07-23 JST

## 再現した根因

AIShellの54 ToDo工程図を公開dashboardから生成する間、Nodeの同一event loop上の
health応答が500msを超えた。旧実装はこれをdaemon死亡と誤判定し、新daemonを起動した一方で
旧daemonを停止できず孤児化した。実環境で11個の孤児を確認し、各processが約5〜7% CPU、
約140MB RSSを消費していた。多重daemonが同じstoreを毎秒再読みすることで、AIShell HTML生成は
28.3秒まで悪化し、直後の再生成は30秒でtimeoutした。

## 修正

- health応答上限を2秒へ更新し、500msを超える正常なbusy応答を許容した。
- descriptorのPIDが生存しているのにhealthをattestできない場合、置換を開始せず
  `DASHBOARD_DAEMON_UNRESPONSIVE`でfail closedするようにした。
- dashboardは`.lattice/todo/manifest.json`のdevice・inode・size・mtime・ctimeが不変の間、
  stable store readを再利用するようにした。読取中のfile identity変化は再読みし、古いstoreを
  新しいfingerprintへ結び付けない。
