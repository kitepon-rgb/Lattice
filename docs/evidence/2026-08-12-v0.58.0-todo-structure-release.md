## 公開操作

1. release candidate `cf104b5c…`をremote mainへ通常pushした。
2. 公開前依存修正commit `59095c77…`を追加し、remote mainへ通常pushした。
3. `npm publish --access public`の`prepublishOnly`でrelease commitのmain着地を再検証した。
4. registryのversion、dist-tag、SHA-1、integrityを取得し、事前packと照合した。
5. `npm install -g @quolu/lattice@0.58.0 --prefer-online`で公開物そのものを導入した。
6. Lattice実repoで`lattice status --json`を実行し、dashboardを0.58.0から再登録した。
7. launchdの`dev.kitepon.lattice.bridge`をkickstartし、0.58.0とheartbeat acceptedを確認した。
8. 公開URLと公開HTMLのstructure projectionを確認した。
9. test helperのCLI入口だけを一時的にglobal install版へ向け、構造ライフサイクルE2E 1/1 passを確認後、
   helper差分を戻した。

Lattice main worktreeに元から存在した`.lattice`、`.team/scripts/done.sh`、room logの変更一覧は、
dashboard再登録の前後で増減していない。公開作業はそれらをcommitへ含めていない。

## Rollback条件

公開後にCLI起動不能、dashboard HTTP不達、bridge heartbeat拒否、または0.58.0固有のデータ破壊が確認された場合、
Macを`@quolu/lattice@0.57.3`へ戻してdashboardとbridgeを再起動する。npm unpublish、remote mainのforce push、
履歴巻き戻しは行わない。修正版は新versionとして公開する。
