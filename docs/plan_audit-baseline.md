# 監査なしで閉じた歴史を、正直に閉じられるようにする — 統括 plan

**工程正本は Lattice store**（plan_key: `audit-baseline`）。本書は目的・思想・判断理由・非目標・
受入条件だけを所有する（2026-07-30 起票、オーナー裁定による）。

## 目的

0.36.0 で入れた終端監査 gate（[ADR 0147](adr/0147-audit-is-on-by-default.md)）に欠陥がある。
**過去に終わった工程まで「監査待ち」にしてしまう。**

## なぜ欠陥か — 監査対象が既に変化している

過去の工程は監査できない。**対象のコードが既に変わっている**からである。それを監査しろと要求すると
起きるのは2つのどちらかで、どちらも gate が誘発する事故になる。

1. 今のコードを見て「問題がある」と言い出す——実際には後の意図的な変更である（誤検出の事件）
2. 中身を見ずに `accept` を押す——**監査の意味を自分で壊す**

0.36.0 の gate は2つを混ぜていた。「これから終わる工程は監査を通ってから完了にする」（正しい）と
「過去に終わった工程も監査記録が無いなら監査待ち」（誤り）である。

## 実害の範囲（実測・2026-07-30）

| store | 監査待ちになった量 |
|---|---|
| Lattice 自身 | 23 plan / 104 ToDo |
| ServerManager | 1 plan / 26 ToDo（**これは正しい指摘**。最近の作業でコードも生きている） |
| bingo | 0 件 |

**0.36.1 は既に公開済みであり、アップグレードした利用者の工程図が過去の完了分で埋まる。**
何が起きたかも、何をすればよいかも画面に出ない。CHANGELOG にも書いていない。

## 思想

- **過去を監査済みに化けさせない。** 監査していないものは、永久に「監査なしで閉じた」と記録され続ける
- **嘘の監査を強いない。** 対象が変化した工程に `accept` を求めない
- **自動で免除しない。** どれを監査し、どれを歴史として畳むかは人／AI が決める。装置は宣言を
  受け取って記録するだけである（推定を実装しない）
- **驚きを画面で説明する。** 札が出た理由と、次に打つコマンドを typed に返す

## 判断理由

| 論点 | 判断 | 理由 |
|---|---|---|
| 過去分を自動で免除するか | **しない** | 「古いから免除」は装置による推定。ServerManager の 26 件は最近の作業で、監査すべき対象である。一律免除はそれを取り逃がす |
| `accepted` を流用するか | **別状態にする** | 監査していないものが監査済みに見える形は、gate の意味を壊す。記録は永久に区別できること |
| 1件ずつ宣言させるか | **一括入口を持つ** | 104 件を手で宣言させたら誰もやらない。やらせない設計は gate をノイズへ変える |
| 対象の変化を機械が判定するか | **しない** | 「変化したか」の判定は意味論的で、計画段階では決定不能。宣言と記録に留める |

## 非目標

- 監査の中身を採点しない（ADR 0147 の非目標を継承）
- 既存の phase 付き plan の挙動を変えない
- store の canonical 形式・digest 計算を変えない
- 「古い工程を自動で畳む」時間ベースの推定を入れない

## 受入条件

1. **「監査なしで閉じた」状態が `accepted` と機械的に区別できる**。journal に理由つきで記録され、
   監査済みとして読める経路が無いことをテストで固定する
2. その状態の plan は工程図で畳まれる（監査待ちの札が外れる）
3. **一括入口**で、アップグレード時点で既に全 task done だった plan をまとめて宣言できる。
   自動実行はしない（明示コマンドのみ）
4. **監査待ちの札が出たときの案内**に、何が起きたか・次に打つコマンドが typed で載る
5. `npm test` 全 green・`npm run ci` 全段 green
6. **release まで届く**: CHANGELOG のアップグレード注意 → commit → push → npm publish →
   npm install → 常駐 daemon 載せ替え → 公開後 smoke
7. 本 plan 自身を Phase gate 付きで運用する
