# ob04: 「未判定はdispatchを塞がない」をProtected behavior化

## 何を作ったか

未判定（witness未宣言＝`coverage: missing`）は「競合が無い」ではなく「まだ調べていない」である。
だからといってdispatchを止めると、ToDoツリー上は並列できるものが多数あるのに工程が止まる。
現行実装は既に塞いでいない（advisoryだけを返す）が、**それは実装の現状であって契約ではない**。
将来の変更が善意でここを壊さないよう、実行可能な形でanchorした。

### anchor test（新規 `test/todo-dispatch-unjudged.test.mjs`・3件）

phase無しplan（T1・T2が並列ready、T3はT1待ち）の実storeで、independence記録の有無を切り替えて
dispatch面を突き合わせる。

1. **記録が無くてもready frontierは通常どおり出る。** 前提として
   `readTodoIndependenceArtifact` が `null` を返すことを先にassertし、その状態で
   `next_ready` が `['T1','T2']`、`recommended_parallelism: 2`、`subset_requires_reason: true`。
   `computeReadyFrontier` も同じ集合を返す。
2. **記録を書いてもdispatch面は1バイトも動かない。** `active_set`／`next_ready`／`blocked`／
   `dispatch_frontier` を `JSON.stringify` でbyte比較し、`frontier_digest` も個別に固定。
3. **競合を宣言した記録でも塞がらない。** `conflicts: [T1×T2 @ src/shared.mjs]`、
   `wave_plan` を2波（`minimum_feasible_waves: 2`）にしても frontier は不変。
   判定結果が「競合あり」でもdispatchの可否は変わらない。

3件目はdesign memoが要求した範囲（`coverage: missing` と coverage 有りの一致）より1段強い。
**判定して競合が出た時が、本当に塞ぎたくなる場面**だからそこをanchorに含めた。room [140] で
範囲外なら落とすと宣言し、異論は出ていない。

### vacuous対策

前campaignで ひなの [46]・みつき [48] が独立に踏んだ問題（両側を互いに比較するだけだと
両方同時に壊れた時に通る）を、2重で防いだ。

- **記録が実際に立ったことを `readTodoIndependenceArtifact` で確認してから比較する。**
  立っていなければ「変わらない」は当たり前で、何も固定していないことになる
- **`next_ready` をリテラルでも固定する**（`['T1','T2']`）。両側が同時に壊れた形を落とす

### ADR 0160 には触っていない

design memoは「ADR 0160（ob07）のProtected behaviorへ明文を入れ」と書いているが、**ob07のmemoも
同じ節を持っている**（「(3)未判定はdispatchを塞がない（Protected）」）。同じ1節を2つのtaskが
所有しており、しかもob04はready・ob07は後段である。ready側がまだ存在しない後段の成果物を作ると、
ob07の担当が「新規作成で上書きするか既存へ追記するか」の分岐を強いられる。

そこで**ob04は anchor test と明文の起草を持ち、ADRファイルはob07が作る**形に分けた（room [139]・
異論なし。みつき [141] も同意）。

**明文の受け渡しは room ではなく `todo note` で行った**——工程の途中で分かった義務を散文へ落とすと
守られない、というのがこのcampaignの主題そのものだからである。

```
$ lattice todo note --plan machine-held-obligations --task ob07 --input <file>
{"schema":"lattice.todo_note_append_result.v1","plan_key":"machine-held-obligations","task_id":"ob07"}

$ lattice todo show --plan machine-held-obligations --task ob07
note_context: notes 1件 / note_head_digest 26bbc54f…
```

ob07をstartした人の `note_context` へ自動で届く。**前campaignで `notes: []` を4人が読み飛ばした
機構に、実際に書き込んだ1件目である。**

## 踏んだ罠（次の人へ）

`lattice todo note --input <file>` は **repo内のpathしか受けない**。repo外を渡すと
`INPUT_UNREADABLE / input_path_outside_repo`、symlinkやrealpath不一致も弾かれる。
scratchpadに書いて渡そうとして踏んだ。repo直下へ一時fileを置いて実行後すぐ消す形にした
（`git status` で残っていないことを確認済み）。`--message` なら回避できるが、複数行は
shellの引用が崩れるので長文は `--input` の方が安全。
