# ap02: 監査待ち判定の共有moduleを作る

担当: ひなの / plan: audit-pending-surface

## 何を作ったか

`src/todo-audit-pending.mjs`（新規）へ監査待ちPhaseの定義を一本化した。

- `AUDIT_PENDING_PHASE_STATUSES` = `Set(['gate_ready', 'reviewing', 'rejected'])`
- `isAuditPendingPhaseStatus(status)` — `null` / `undefined` / 未知の値は `false`
- `auditPendingNextCommands(planKey, phaseId, status)` — 打てるコマンド行の配列

次コマンドは `src/todo-store.mjs` のPhase遷移guard（437-474行）と、`src/todo-cli.mjs` の
argv受理形（2637-2662行）の両方に一致させた。実行すれば必ず弾かれる遷移を案内しない。

| 状態 | 案内するコマンド |
| --- | --- |
| `gate_ready` | `lattice todo phase review ... --reason <text>` / `lattice todo phase close-unaudited ... --reason <text>` |
| `reviewing` | `lattice todo phase accept ... --input <file>` / `lattice todo phase reject ... --input <file>` |
| `rejected` | `lattice todo phase reopen ... --reason <text>` |

書式は `lattice todo phase ...` のフル形にした。`src/project-cli.mjs:274-278` の
`next_action.command` が `lattice ...` のフル形なので、ap04がそのまま載せられる形に揃えている。

監査待ちでない状態を渡された時は空配列へ丸めず `AUDIT_PENDING_STATUS_INVALID` を投げる。
呼び出し側の誤りを黙って「案内なし」へ変換すると、監査待ちが表に出ない事故と外形が同じになる。

## 既存の重複を置換した

design memoが指す二重定義を両方importへ置き換えた。定義は1箇所になった。

- `src/todo-gantt-scope.mjs:58` のローカル `AUDIT_PENDING_PHASE_STATUSES` を削除し、
  `isAuditPendingPhaseStatus` の呼び出しへ差し替えた
- `src/todo-dashboard-registry.mjs:23` のローカル `TODO_DASHBOARD_ATTENTION_PHASE_STATUS` を削除し、
  `todoDashboardMemberNeedsVisibility` を同じ関数へ差し替えた

`grep -rn 'AUDIT_PENDING_PHASE_STATUSES|TODO_DASHBOARD_ATTENTION_PHASE_STATUS' src` で、
`src/` 側に残る定義が新moduleの1件だけであることを確認した。

## 移さなかったもの（意図的）

`todo-gantt-scope.mjs` が持つ `lattice.todo_plan.v4` / `v5` の除外filterは共有moduleへ移していない。
あれは「監査待ちとは何か」の定義ではなく、ganttがどこまでfoldを止めるかという当該moduleの方針である。
移せば宣言Phase planのfold挙動が他の消費者の都合で変わる（design memoの非目標）。その旨を
コード内コメントへ明示した。
