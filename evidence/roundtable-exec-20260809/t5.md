## どう確認したか

### 1. 文書へ書いた挙動を実物で確かめた（推測で書いていない）

禁止操作の一覧は engine の実物から取った。`src/runtime-engine.mjs:44` の
`FORBIDDEN_OPERATIONS = ['push','branch','merge','rebase','reset','stash']`、commit を外す理由は
同 :34-43 のコメント（ADR 0139）。packet へ載る経路は `buildExecutorPackets`（同 :173）、
契約は `validateExecutorPacket`（`src/runtime-contracts.mjs:574-603`）。
scope 外書込が「弾かれず観測に出る」ことは `detectCheckpointFindings`
（`src/runtime-diff-observer.mjs:263-281`・`undeclared_write`）。
worktree の生成と終端撤去は `src/runtime-scripted-worktree.mjs:66-104`
（`git worktree add --detach` / `git worktree remove --force`）。

さらに、文書が席へ約束している git の挙動を使い捨て repo で実測した（scratchpad・本repo外）:

| 確かめたこと | 結果 |
|---|---|
| worktree の HEAD 状態 | `## HEAD (no branch)`＝detached |
| gitignore 済み資産（`node_modules`）が worktree に在るか | **無い**（`src` のみ） |
| worktree 内 commit は base の子孫か | `git merge-base --is-ancestor` = yes |
| worktree 内 commit で canonical が汚れるか | `git status --short` 0行 |
| `git worktree remove --force` 後の木 | 消えた |
| 同 commit object | 残る（`git cat-file -t` = commit）が `git branch --contains` は空＝**到達不能**、`git fsck --unreachable` に載る |

→ 文書の「成果の正本は席の commit ではなく Lattice が撮った observed diff」「commit したから残ると
思わない」は、この実測に基づく。

### 2. template を壊していないこと

`member.md` は `setup.sh:67` が sed で `{{PLAN_KEY}}` / `{{CLAIM_SCOPE}}` を置換する template である。
同じ sed を手で回して、①残留プレースホルダ 0 ②追加節の見出しが描画結果に出る、を確認した
（未置換プレースホルダは追加前と同じ2種のみ）。sed の区切りが `|` なので、追加文に `|` を入れていない。

## 見てほしい点（監査依頼）

1. **`[完了] tN` を bridge の完了検出源にしてよいか。** 席の自己申告を state 遷移の合図にだけ使い、
   diff は Lattice が撮る（請求項9の規律）という切り分けのつもりだが、t4 実装者から見て room 発言を
   parse 源にするのが妥当か。room を落とすと完了が拾えなくなる経路が残る
2. **注入文の書式が t4 の出力側と噛み合うか。** 行頭一致 parse を席側にも課しているので、
   bridge 側の生成と席側の期待がずれると静かに壊れる
3. **`node_modules` を worktree 内で install させる指示の妥当性。** 観測の除外対象
   （`src/runtime-io-sentinel.mjs:40` `DEFAULT_IO_EXCLUDES`）なので diff は汚さないと読んだが、
   実 run の checkpoint 観測で本当に出ないかは実 daemon での確認が要る（t7 受入で見える）
