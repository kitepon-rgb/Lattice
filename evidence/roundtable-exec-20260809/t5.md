## どう確認したか

### 1. 文書へ書いた挙動を実物で確かめた（推測で書いていない）

禁止操作の一覧は engine の実物から取った。`src/runtime-engine.mjs:44` の
`FORBIDDEN_OPERATIONS = ['push','branch','merge','rebase','reset','stash']`、commit を外す理由は
同 :34-43 のコメント（ADR 0139）。packet へ載る経路は `buildExecutorPackets`（同 :173）、
契約は `validateExecutorPacket`（`src/runtime-contracts.mjs:574-603`）。
scope 外書込が「弾かれず観測に出る」ことは `detectCheckpointFindings`
（`src/runtime-diff-observer.mjs:263-281`・`undeclared_write`）。
worktree の生成と終端撤去は `src/runtime-scripted-worktree.mjs:66-104`
（`git worktree add --detach` / `git worktree remove --force`）。

さらに、文書が席へ約束している git の挙動を使い捨て repo で実測した（scratchpad・本repo外）:

| 確かめたこと | 結果 |
|---|---|
| worktree の HEAD 状態 | `## HEAD (no branch)`＝detached |
| gitignore 済み資産（`node_modules`）が worktree に在るか | **無い**（`src` のみ） |
| worktree 内 commit は base の子孫か | `git merge-base --is-ancestor` = yes |
| worktree 内 commit で canonical が汚れるか | `git status --short` 0行 |
| `git worktree remove --force` 後の木 | 消えた |
| 同 commit object | 残る（`git cat-file -t` = commit）が `git branch --contains` は空＝**到達不能**、`git fsck --unreachable` に載る |

→ 文書の「成果の正本は席の commit ではなく Lattice が撮った observed diff」「commit したから残ると
思わない」は、この実測に基づく。

### 4. 自分の指示を実測して1つ撤回した（reopen → 訂正 → 閉じ直し）

初版の member.md は「依存が要るなら worktree 内で install してよい（`node_modules` は観測の除外対象
だから diff を汚さない）」と書いていた。**これは誤りだった。** 実測で潰したので記録する。

誤りの中身: `DEFAULT_IO_EXCLUDES`（`src/runtime-io-sentinel.mjs:40`）は I/O sentinel の早期警報の話で、
checkpoint 観測は別経路である。`captureWorktreeDiff` は
`git status --porcelain=v1 --untracked-files=all --ignored=matching`（`runtime-diff-observer.mjs:176-178`）
で撮り、**gitignore 済みの書き込みも意図的に拾う**——gitignore 経由の scope violation 迂回を塞ぐため
（同 :174-175 のコメント）。ignored directory は内包 file へ展開される（同 :196-209）。

実測（`captureWorktreeDiff` / `detectCheckpointFindings` を直に呼ぶ probe。使い捨て repo・本repo外）:

| 状況 | 結果 |
|---|---|
| 宣言 scope 内だけを変更 | entries = 1（`src/a.mjs`） |
| worktree 内で ignored file 300本を生成（install 相当） | **`captureWorktreeDiff` が落ちる**: `diff entry数が上限を超える: 301`（`MAX_DIFF_ENTRIES=256`） |
| ignored file 5本だけ | entries = 5・**全部 `undeclared_write`** |

→ install した席は、自分の task の checkpoint 観測を落とす。

**では依存はどうするのか。** install 無しで解決する。worktree は `<repo>/.lattice/runs/<run>/worktrees/<id>/tree`
＝**repo 配下**に切られるので、Node の bare specifier 解決が親ディレクトリを遡って canonical の
`node_modules` に当たる。実測（fake package を canonical にだけ置いた使い捨て repo）:

| worktree の置き場 | worktree 内 ESM の `import "fakedep"` |
|---|---|
| `<repo>/.lattice/runs/r1/worktrees/w1/tree`（repo 配下） | **解決する**（canonical の node_modules へ当たる） |
| repo の外（`/tmp/...`） | `ERR_MODULE_NOT_FOUND` |

worktree を run store 配下に置く設計（`runtime-scripted-worktree.mjs:55-58`）は、この一点だけでも効いている。
残る注意は、当たるのが **canonical に入っている版**であって worktree の package.json が要求する版ではない
こと——lockfile を動かす task の検証結果は疑う必要がある。文書へはこの形で書いた。

## 見てほしい点（監査依頼）

1. **`[完了] tN` を bridge の完了検出源にしてよいか。** 席の自己申告を state 遷移の合図にだけ使い、
   diff は Lattice が撮る（請求項9の規律）という切り分けのつもりだが、t4 実装者から見て room 発言を
   parse 源にするのが妥当か。room を落とすと完了が拾えなくなる経路が残る
   （下ごしらえの読みでは、bridge は既に SSE を購読して message を parse しているので、
   経路自体は追加にならない: `peertable/skill/scripts/wakeup-bridge.mjs` の SSE ループ）
2. **注入文の書式が t4 の出力側と噛み合うか。** 行頭一致 parse を席側にも課しているので、
   bridge 側の生成と席側の期待がずれると静かに壊れる
3. **上の「4.」の訂正が本当に正しいか。** probe は `captureWorktreeDiff` を直に叩いたもので、
   実 daemon の checkpoint 経路（`runtime-direct-os-observer.mjs:191` が同関数を注入している）は
   t7 受入で実物を見る必要がある。私の測定器を疑うなら、probe の①②③を同じ手で再現してほしい

## 再現手順（probe は scratchpad で回した。repo へは置かず、ここへ全文を残す）

```js
// ignored fileの大量生成がcheckpoint観測へどう映るか
import { mkdtemp, mkdir, writeFile, rm } from 'node:fs/promises';
import { execFileSync } from 'node:child_process';
import path from 'node:path';
import os from 'node:os';
import { captureWorktreeDiff, detectCheckpointFindings } from '<Lattice>/src/runtime-diff-observer.mjs';

const root = await mkdtemp(path.join(os.tmpdir(), 'probe-'));
const repo = path.join(root, 'repo');
await mkdir(path.join(repo, 'src'), { recursive: true });
const git = (...args) => execFileSync('git', args, { cwd: repo, encoding: 'utf8' }).trim();
git('init', '-q', '.'); git('config', 'user.email', 't@e'); git('config', 'user.name', 't');
await writeFile(path.join(repo, '.gitignore'), 'node_modules/\nruns/\n');
await writeFile(path.join(repo, 'src/a.mjs'), 'export const a = 1;\n');
git('add', '.gitignore', 'src'); git('commit', '-qm', 'base');
const base = git('rev-parse', 'HEAD');
const wt = path.join(repo, 'runs', 'r1', 'tree');
git('worktree', 'add', '--detach', wt, base);

await writeFile(path.join(wt, 'src/a.mjs'), 'export const a = 2;\n');
console.log('①', (await captureWorktreeDiff({ worktreePath: wt, baseSha: base })).diff.entries.length);

await mkdir(path.join(wt, 'node_modules/pkg'), { recursive: true });
for (let i = 0; i < 300; i += 1) await writeFile(path.join(wt, `node_modules/pkg/f${i}.js`), `${i}\n`);
try { await captureWorktreeDiff({ worktreePath: wt, baseSha: base }); }
catch (error) { console.log('②', error.message); }   // -> diff entry数が上限を超える: 301
```

依存解決のほうは shell だけで再現できる（`node_modules/fakedep` を canonical にだけ置き、
worktree を repo 配下と repo 外の2箇所に切って、worktree 内の ESM から `import "fakedep"` する）。
repo 配下は解決し、repo 外は `ERR_MODULE_NOT_FOUND` になる。
