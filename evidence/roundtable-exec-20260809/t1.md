# t1 work-order adapter controller

## 作成したもの

- `lattice.run_work_order.v1` と `lattice.run_work_report.v1` の exact-key 契約、canonical JSON + LF、packet digest と order digest の検証を追加した。
- `work-order` adapter controller と実行可能な `lattice-work-order-adapter` bin を追加した。controller は spool の `orders/` と `reports/` を 0700 で準備し、order を 0600 の一時ファイルへ書いて fsync・rename で公開する。
- report は regular file・0600・非 symlink・上限内・canonical bytes のものだけを受理する。新しい order の公開前に同一 packet digest の古い report を削除し、stale `done` を誤受理しない。
- bridge が辞退を処理している間は operation heartbeat を維持し、最初の `working` report で受諾した実席 PID を固定する。`done` は遷移合図だけに使い、terminal receipt の diff は controller が worktree から取得する。
- 長寿命の対話席は `worker_process.process_membership='dynamic_group'` として扱う。root PID・start identity・PGID を固定し、barrier では process group 全体を停止したうえで、その時点の全子孫が同じ PGID に属し、無関係な group member がなく、全員が T/Z であることを controller と supervisor が独立観測する。barrier の事前確認失敗時は group を `SIGCONT` して task を running に戻し、held successor では同じ group を再開して次の order を渡す。従来の scripted worker は `static` membership のまま既存の exact child 契約を維持する。
