# t10 run observe出力の進行中要約（要否確認）

- 実施者: kanade（かなで）
- 日付: 2026-08-09
- 結論: **追加実装は不要**。現行 `lattice.run_observation.v1` が進行中監視に必要な要約を既に持つ。

## 受入条件と判定

計画正本 `docs/plan_roundtable-execution-integration.md` は、現出力で足りる場合に
「不要と確認した」証跡で閉じることを認めている。t8 の bridge が polling して room へ可視化するために必要な情報を
公開 CLI と projection の実物で確認した。

| 必要な観測 | 現行出力 | 判定 |
|---|---|---|
| 現在進行中の TODO | `running`（TODO ID の exact 配列） | 充足 |
| 完了・受理済みの TODO | `terminal` / `accepted`（TODO ID の exact 配列） | 充足 |
| 停止要因の有無 | `hold_count` / `conflict_count` / `freeze_active` | 充足 |
| run の終端 | `closed` | 充足 |
| polling 間の変化検知 | `event_count` / `events_digest` / `result_digest` | 充足 |

`src/runtime-projection.mjs` では `executor_dispatched` で TODO を `running` へ追加し、
`executor_terminal` または `receipt_accepted` で除去する。`executor_terminal` は同じ TODO を `terminal` へ、
`receipt_accepted` は `accepted` へ追加する。`src/runtime-cli.mjs` の `runObserve` はこの保存 event 列から再構成した
配列をそのまま公開するため、可変 summary や executor 自己申告に依存しない。

したがって別の文章要約・件数・状態ラベルを足すと、同じ事実の二重表現と公開 wire の追加になるだけで、
t8 の polling 消費者へ新しい情報を与えない。コード・schema・test は変更しない。
