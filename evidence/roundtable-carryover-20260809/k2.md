# k2 runtime store世代不一致のtyped診断

## 対象と非対象

- 現行CLIが既知のruntime store familyの将来世代を読んだ時、一般的な破損へ潰さず
  `UNSUPPORTED_RUNTIME_STORE_VERSION` として返す。
- 診断detailはartifactごとの`observed_schema` / `expected_schema`、
  `observed_version` / `expected_version`、更新手順を保持する。
- 既に配布済みの古いbinary自身は変更できない。古い導入物の検出と更新配線はdotagents所有であり、
  このToDoの対象外とした。

## 実装

- 初版 `d5fd086` でrun-meta、committed pointer、epoch bundleと、run-metaが束縛する
  run/control/bundle schemaを既知familyの将来世代として検出するようにした。
- 更新手順は `npm install -g @quolu/lattice@latest --prefer-online` をtyped detailへ格納した。
- 未知familyは既存の`UNSUPPORTED_RUN_STORE_SCHEMA`、現行世代の破損は
  `INVALID_RUN_STORE`のまま維持した。
- 自己監査で、壊れた現行run-meta/pointer envelope内のfuture文字列を先に読むと、
  破損をunsupportedへ誤分類し得る順序問題を発見した。補正 `75ef762` で
  exact envelopeとself-digestの検証を子schema世代判定より先行させた。
  正当な現行envelopeが宣言するfuture childだけはtyped診断へ到達する。
