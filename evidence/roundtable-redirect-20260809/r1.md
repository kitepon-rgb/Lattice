# r1 pull型への組み替え: Lattice側

## 実装

- `run start --selection pull`を、起動時のtask列挙やbase固定を持たないpull専用run storeとして追加した。
- `run intake`で、同一active plan versionのliteral `todo start`、intake時canonical HEAD、witness／independenceを束縛し、isolated detached worktreeを先に供給してから`none`または`hold`を返すようにした。
- planning conflictは後着をholdし、runtime diffは宣言外変更・他active intakeとの競合を観測してleaseをrevokedにする。attach済みworkerへsignalする前はpid／process start identity／argv digestを毎回OSから再認証する。
- attach inputは生観測の`started_identity`と`argv_digest`だけを受け、canonical self-digestを消費者へ要求しない。run storeにはLatticeが独立再観測して構築したprocess identityとargv digestだけを保持する。raw argvを渡した場合も値を診断へ出さない。
- acceptをsame-version・same-actorのliteral `todo done` digestと独立worktree checkpointへ束縛し、landing receiptへaccepted headを投影した。closeはintake membershipだけを対象にし、0件は`RUN_EMPTY`、未完了は拒否、完了後は冪等にした。
- legacy run readerとのschema dispatchを一方向に分け、pull／legacy artifactの双方向混在と未知schemaをtyped errorで拒否した。pullへlegacy専用commandを渡した場合もlegacy readerへ入る前にmode mismatchへ閉じる。
- independence全体がunknownならtask局所unknownが空でもholdし、conflictと向き付きprecedenceの双方を後着intakeのplanning holdへ投影した。precedence predecessorがTodo正本で既にdoneかつ同runにintakeされていなければ、後続だけのopen membershipを許可する。同runにintake済みならTodo done後もruntime acceptまで後続leaseを解放しない。
- observe/statusの各intakeへstart actor bindingを投影し、bridgeがTodo journal内部構造を別読せず介入先を決められるようにした。
