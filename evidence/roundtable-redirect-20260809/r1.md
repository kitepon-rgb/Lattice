# r1 pull型への組み替え: Lattice側

## 実装

- `run start --selection pull`を、起動時のtask列挙やbase固定を持たないpull専用run storeとして追加した。
- `run intake`で、同一active plan versionのliteral `todo start`、intake時canonical HEAD、witness／independenceを束縛し、isolated detached worktreeを先に供給してから`none`または`hold`を返すようにした。
- planning conflictは後着をholdし、runtime diffは宣言外変更・他active intakeとの競合を観測してleaseをrevokedにする。attach済みworkerへsignalする前はpid／process start identity／argv digestを毎回OSから再認証する。
- attach inputとrun storeにはraw argvを認めず、`process_start_identity`と`argv_digest`だけを保持する。raw argvを渡した場合も値を診断へ出さない。
- acceptをsame-version・same-actorのliteral `todo done` digestと独立worktree checkpointへ束縛し、landing receiptへaccepted headを投影した。closeはintake membershipだけを対象にし、0件は`RUN_EMPTY`、未完了は拒否、完了後は冪等にした。
- legacy run readerとのschema dispatchを一方向に分け、pull／legacy artifactの混在と未知schemaをtyped errorで拒否した。

## 検証

- `node --test test/runtime-pull-intake-cli.test.mjs` — green。pull start/intake、未start拒否、intake時HEAD、planning hold、到達不能base hold、accept/landing/close冪等性、raw argv非永続化・非診断出力、start identity decoy、同pid二重attach、legacy/mixed store拒否を確認。
- `node --test test/runtime-conflict-cli.test.mjs test/runtime-landing-cli.test.mjs` — green。既存legacy conflict／landing契約の互換性を確認。
