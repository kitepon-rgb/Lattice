# ap05: dashboard／ganttヘッダへ監査待ちを出す

担当: ひなの / plan: audit-pending-surface

## 何を作ったか

工程図のヘッダ（`.diagram-toolbar`、プロジェクト名の直後）へ監査待ちの札を出した。

```
Lattice 依存工程図  [監査待ち 1件: audit-pending-surface/terminal-audit (gate_ready)]  − 等倍 ＋ 全体表示
```

- 文面は `監査待ち N件: <plan>/<phase> (<status>) · ...`。design memo の指定どおり。
- 判定は ap02 の共有module（`isAuditPendingPhaseStatus`）を使う。状態集合をここで書き直していない。
- 監査待ちが1件も無ければ札そのものを出さない（`accepted` / `closed_unaudited` だけの時）。

**dashboard と gantt は別物ではなかった。** `bin/lattice-dashboard.mjs:94` は
`renderTodoGanttForProject` の出力をそのまま配信しているので、面は1つで、この1箇所の変更が両方へ届く。
`todoDashboardMemberNeedsVisibility`（ap02 で共有moduleへ寄せた側）が監査待ちprojectを
dashboard の配信対象に保つので、「監査待ちだけが残ったproject」でも図が配信され、そのヘッダに札が出る。

### 幅の扱い

内訳が長い時は CSS（`overflow:hidden` / `text-overflow:ellipsis`）で省略し、全文は `title` に残す。
ただし `min-width:9em` を置いて、**件数（`監査待ち N件`）は決して潰れない**ようにした。
省略されるのは内訳であって件数ではない。件数まで消えると、幅の都合で監査待ちの存在自体が
隠れることになり、この工程が直している事故と同じ形になる。

### renderer version

`TODO_GANTT_RENDERER_VERSION` を `lattice.todo_gantt_renderer.v18` → `v19` へ上げた。
描画出力が変わった時に上げるのが既存の作法（`docs/handoff_lattice_gantt_ui_v7.md:149` の前例）。
`test/todo-gantt-render.test.mjs` の pin 2箇所も追従させた。

## 共有moduleへの追加（ap02 の module を1つ拡張した）

`src/todo-audit-pending.mjs` へ `auditPendingPhasesOf(readModel)` を追加した。
store read model の `member.phases` を歩いて監査待ちだけを `{plan_key, phase_id, status}` で返す
（plan_key→phase_id順）。既存3 export は無改変。

返すのを3キーに絞ったのは、消費者ごとに要る付随情報（`implicit` / `required_evidence_slots` /
`next_commands`）の形が違うためで、ap03 の entry 形（room [14]）を先回りして固定しない。
room [22] で全員宛に共有し、ap03 が使うかは ap03 の判断に委ねた。

## どう確認したか

**焦点testは `LATTICE_DASHBOARD_AUTOSTART=0` を付けて実行した**（room [24] のすずめの指摘。
付けないと test 中の CLI 呼び出しが実 dashboard daemon を起こして製品と無関係に赤くなる）。

新規 `test/todo-gantt-audit-pending.test.mjs`（6 test）。うち2つは**実store**で通した——
手で組んだ read model は「その形が来たらどう描くか」しか示さず、store が実際にその形を作るかを
示さないため。

| 種別 | 内容 | 結果 |
| --- | --- | --- |
| 実store | 一時repoに v3 plan を作り全taskをdone→`renderTodoGanttForProject` | `監査待ち 1件: audited/terminal-audit (gate_ready)` |
| 実store | 続けて `phase_close_unaudited` を記録→再描画 | 札が消える |
| 合成 | gate_ready で札が出る | pass |
| 合成 | accepted / closed_unaudited / active では出ない | pass |
| 合成 | 複数planが件数と plan_key 順の内訳で並ぶ | pass |
| 合成 | `phases` を持たない read model でも描画が壊れない | pass |

`src/todo-audit-pending.mjs` の projection にも unit test を2件追加（並び順・空store）。

- `LATTICE_DASHBOARD_AUTOSTART=0 node --test test/todo-gantt-audit-pending.test.mjs
  test/todo-gantt-render.test.mjs test/todo-gantt-selfcontained.test.mjs test/todo-gantt-live.test.mjs
  test/todo-audit-pending.test.mjs` → **tests 53 / pass 53 / fail 0**
- 別途 `test/todo-terminal-audit.test.mjs` `test/todo-close-unaudited.test.mjs`
  `test/todo-gantt-scope.test.mjs` `test/todo-note-gantt.test.mjs`
  `test/todo-gantt-independence.test.mjs` 込みで **82 pass / 0 fail**
- `npm run check` → `syntax check passed: 140 files`
- 生成HTMLを実際に書き出して DOM 位置と CSS 同梱を実測（`.diagram-toolbar` 内、
  `.project-heading` の直後に `<span class="audit-pending-chip">`、CSS 規則も同一ファイルに同梱）
- 本repoの実storeでは監査待ち0件（`accepted` 13 / `closed_unaudited` 23 / `active` 1）なので、
  現時点の Lattice 自身の図には札は出ない。陰性側の実測としては正しい。
