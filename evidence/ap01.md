# ap01: Phase定義アクセサをexportする

## 何を作ったか

`src/todo-store.mjs` に `export function todoPhaseDefinitions(plan)` を追加した（`phasesOf` の直下）。
中身は `phasesOf(plan)` をそのまま返すだけで、判定も合成もこの関数では行わない。

- phase無しplan（`lattice.todo_plan.v1/v2/v3`）へ渡すと、暗黙の terminal-audit Phase 定義
  `{phase_id:'terminal-audit', title:'終端重監査', gate_policy:'terminal-audit',
  predecessor_phase_ids:[], required_evidence_slots:['terminal-audit']}` が1件返る。
- Phase plan（v4/v5/v7）へ渡すと `plan.phases` をそのまま返す。
- `plan.schema` が未定義でも `isPhaselessTodoPlanSchema(undefined)` が true なので全域で、
  存在しない `plan.phases` を読みに行かない。

これで `todo-status.mjs` 側は「終端監査が何を要求するか」を再導出せずに読める。定義の正本は
`terminalAuditPhase()` 1箇所のままである。

新規exportのみで既存の呼び出し経路は一切変えていない。import循環が無いことは確認済み
（`todo-store.mjs` は `todo-status.mjs` を import していない）。

## どう確認したか

新規 `test/todo-phase-definitions.test.mjs`（4 test）。既存ファイルへ足さず新設したのは、
並行作業中の他メンバーと同じファイルで衝突しないため。

1. phase無しplan v1/v2/v3 → 暗黙 terminal-audit Phase 定義が slots 込みで返る
2. `{}` / `{tasks:[]}` のような synthetic read model でも壊れず同じ定義を返す（全域性）
3. Phase plan v4/v5/v7 → 合成せず `plan.phases` をそのまま返す
4. 返った `required_evidence_slots` が、実storeの終端監査gateが実際に要求する slot と一致する
   — 実store（v1 plan・git init 済み temp root）で T1 を done にして terminal-audit を gate_ready に
   し、`phase_review` の後、宣言と違う slot_id での `phase_accept` が
   `STORE_INCONSISTENT / phase_accept_binding_invalid` で拒否されること、
   `todoPhaseDefinitions()` が返した slots そのままなら `accepted` になることを実測した。
   定義が二重化していれば、この2つの成否が逆になる。
