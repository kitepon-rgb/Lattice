# s5 規範の1行: ToDo の内側にリストを作らない

- 実施者: tsumugi（つむぎ）
- 日付: 2026-08-09
- 実体: peertable `skill/templates/member.md`（越境）・commit `a4ab240`

## 何を書いたか

作業ループへ1項目足した（既存の 6 の位置に入れ、以降を繰り下げた）:

> **ToDo の内側にリストを作らない。溜まったらグラフへ出す。** 実装中に「あれもやる」「これも要る」が
> 増えて、頭の中や作業メモに**チェックリストが生えてきたら、それは ToDo が1つでなくなった合図**である。
> 1つの ToDo の内側で消化せず、**A1..An ＋ 残余 A' へ分けてグラフ（工程正本）へ出す**。

添えた3点:

- **装置は思考の中の暗黙 gate を検出できない。** 宣言が動いて初めて `scope_expanded`（s1）に出る。
  **行動へ出る前の相は席が自分で捕まえるしかない**——これが s5 の存在理由である
- **分けるのは遅らせるためではない。** 並列に取れるようになり、監査も受入も分かれて軽くなる
- **膨張の種類は AI にしか分からない。** 装置は「N 回膨張した」「合流点だ」までしか言わない。
  上流の契約確定への追従／自分の変更の後始末／元から在った面の見落とし／思いつきで盛った分の
  区別は席がやる（**2026-08-09 実測: 1つの ToDo に前3種が同時に出た**——r2）

## なぜこの文言か

**私自身が今日この失敗をした側**なので、抽象論ではなく実測から書いた。

r2（pull 型への組み替え）では宣言境界が4回広がった:
```
pt-launch-seat                              上流由来（r1 の attach 契約確定に追従）
pt-skill-md                                 自変更由来（配車撤去で起動 command が壊れた）
pt-charter-md / pt-setup-sh / pt-teardown-sh 見落とし由来（元から向きが埋まっていた）
src/todo-cli.mjs（s1 側）                    自変更由来（実装中に必要と分かった）
```
**どれも「盛った」ではないのに、宣言は膨らんだ。** そして**私は最後の1件で、
宣言を見に戻らずに書いた**（[1101] で自己申告）。**規範が要るのはこの瞬間である**——
機械が教えてくれるのは commit した後で、**手が動いている最中には誰も止めてくれない。**

## どう確かめたか

- **文言は member.md（席の作法の正本）だけに置いた。** `SKILL.md` には入れていない——
  席の作法は member.md が正本で、二重化しない規律（既存の SKILL.md の記述どおり）。
  実際に `grep` して SKILL.md 側に無いことを確認した
- 番号の繰り下げ（7→8 … 10→11「1 へ戻る」）を実物で確認した
- **`.team/roles/member.md`（生成物）は触っていない。** setup が templates から作るので、
  次の卓から効く（生成物を手編集しない方針・mio [981]）

## やっていないこと

- **閾値や自動検出は作っていない。** s5 は規範であって機械ではない。
  「N 個以上のチェックリストで警告」のような形は**思考の中の相を検出したことにならない**
- **s2（advisory の勧告）とは別物。** s2 は宣言が動いた後に装置が促す面で、
  s5 は動く前に席が自分で捕まえる面である。**二重化ではなく、担当する相が違う**
